# Socials Pre-drafted Replies

A local-only Chrome extension for answering "What are you working on?" posts on X and Facebook. You keep a pool of pre-written replies per project. When you click into a reply box, a small bar of buttons appears, one per project you picked for today. Click one and the next unused draft for that project is pasted into the box. You review it and press Send yourself.

Every draft is used once. Used drafts are recorded and never offered again, because X penalizes duplicate posting.

Optionally, on X, the extension can ask [SubQ](https://subq.ai)'s decision model which of your drafts fits the post you're replying to, and offer the best match first.

It also keeps a list of your X followers and the people you follow, built only from what you scroll past, and marks every post author with how you're connected. That shows you who is new to your network without paying for X's API.

**What it doesn't do:** it never clicks the site's buttons, never sends, never navigates, and never moves the mouse. It only reads the post you're replying to and inserts text into the reply box you're already in, when you click one of its buttons. Your data, including the follower lists, stays in your Chrome profile and this folder; the only thing that ever leaves is the SubQ request described below, and only if you add a SubQ key.

## Install

1. Clone this repo.
2. Build the drafts file: `node make-drafts.js` (Node 18+, no dependencies).
3. Open `chrome://extensions`, turn on **Developer mode**, click **Load unpacked**, and select the `extension` folder.
4. Click the extension's toolbar icon to open the side panel.
5. Under **Settings → Project folder**, click **Connect** and choose this repo's folder (the one with `make-drafts.js`). Chrome asks once whether the extension may edit files there; allow it. This lets the side panel save your rules and record used drafts.

## Use

1. In the side panel, switch on up to 5 projects. They show under **Today**.
2. On X or Facebook, click into a reply box. The buttons appear above or below it, each with the number of drafts left.
3. Click a button. The draft is pasted and recorded as used. Review it and press Send.
   Don't like it? Click again: the box is cleared and the next draft goes in. Both count as used.
4. A button greys out when its project has no drafts left.

After changing the extension's code, click the reload arrow on its card in `chrome://extensions`, then reload your X and Facebook tabs. Changing drafts or rules needs no reload.

## Files to customize

These are the files meant to be edited. Everything else is the extension itself.

| File | What to put in it | Required |
| --- | --- | --- |
| `drafts/projects.md` | The facts about each of your projects that drafts may claim: what it is, links, how it works. One heading per project. | Yes |
| `drafts/<project>.txt` | One file per project. The first line is `# Project Name`, then one draft per line. The repo ships with three examples (`my-app.txt`, `side-project.txt`, `connect.txt`); replace them. | Yes |
| `extension/DRAFTING-RULES.md` | Your DOs and DON'Ts for every draft: tone, length mix, emojis, links, things to never say. Also editable in the side panel's **Drafting rules** card, which saves automatically. | Yes, review it |
| `ICONS` in `extension/store.js` | An icon and color per project, matched by lowercase project name. Projects without an entry get a generic icon. | Optional |
| `drafts/voice.md` | Replies you wrote yourself, used as a style reference. Generated by `node make-voice.js "<your X replies export.json>"`; not committed. | Optional |
| SubQ key and model | Entered in the side panel under **Settings → Rank drafts for each post**, stored only in your Chrome profile. | Optional |

Then rebuild:

```bash
node make-drafts.js
```

It writes `extension/drafts.json`, which the extension reads by itself: when the side panel opens, when you click into a reply box, every 5 minutes, when Chrome starts, and when you click the sync button in the side panel header. No import or reload needed.

The builder refuses to write the file if a draft is an exact duplicate, over 8,000 characters (Facebook's comment limit), has more than 2 emojis, is too similar to another draft in the same project, or is too similar to one you've already posted. It warns when more than a third of a project's drafts have emojis.

```bash
node make-drafts.js --status         # per project: unused, posted, refill need, long-post and emoji share
node make-drafts.js --pull-archive   # also pick up a manual "Export used drafts" file from ~/Downloads
```

A project is refilled when it drops below 200 unused drafts, back up to 250. 250 fits one SubQ ranking request (SubQ allows 255 options per question).

## Writing drafts with Claude Code or Codex

The `replenish-drafts` skill does the whole loop. It reads your rules, project facts and (if present) `drafts/voice.md`, works out which projects have dropped below 200 unused drafts, refills them to 250 in the length and emoji mix your rules ask for, and rebuilds until the checks pass.

- **Codex** loads it from `.agents/skills/replenish-drafts/`.
- **Claude Code** loads it from `.claude/skills/replenish-drafts/`, a link to the same folder.

Start either tool in this folder and ask it to replenish the drafts. Open the side panel first so the used-drafts list in `drafts/used/` is current. Run unattended (for example on a schedule), it adds at most 50 drafts per project per run and stops early when nothing is below 200.

## Best match for each post (X, with SubQ)

Optional. When you open a reply to a post on X, the extension reads that post's text (only the post's text, not names or counts) and its background script asks SubQ's [Decisions API](https://docs.subq.ai/endpoints/decisions-api/) (`api.subq.ai/v1/systemone`, model `subq-snap-1.1` by default) to rank today's unused drafts for it. SubQ Snap is a decision model, not a text generator: it answers a choice question with a probability for every option.

- **Round 1, one request per project, all at once:** "which of these drafts best fits this post?" with every draft of that project as an option. More than 255 drafts are ranked in batches, then the best of each batch go through a playoff request.
- **Round 2, for the star:** the top 50 of every project (fewer with 6 or more projects, to stay under 255) in one request, "which is the best reply overall?".
- Ranking starts as soon as X's reply pop-up shows the post, before you click into the box, and is remembered per post.
- A gold star button appears first in the bar. It shows "…" while ranking, then gives the best match; click again for the next best. Its tooltip shows the post it ranked for. Each project button hands out that project's drafts in its own ranked order.
- If a request fails, the affected buttons use the normal order. Hover the star to see why.

Set it up under **Settings → Rank drafts for each post**: paste your SubQ API key (from [console.subq.ai](https://console.subq.ai)), click **Save**, then **Test**. Test also switches to a model your key is allowed to use. The key is stored only in your Chrome profile and used only by the extension's background script; the panel shows its first 3 and last 4 characters. Facebook isn't ranked.

## Follower tracker: who is already in your network

X has no search filter for people outside your network, and its official API is expensive. The extension builds the lists from what's on your screen instead.

### Set it up

1. Open X in the same Chrome profile. The extension finds your handle from X's **Profile** link in the left sidebar; you don't enter it anywhere.
2. Open your own profile once, at `x.com/<your-handle>`. This records your follower and following counts, so the side panel can show how complete the lists are.
3. Scroll your **Followers** page, `x.com/<your-handle>/followers` (the **Verified followers** tab counts too), all the way down. Every person shown is added to your followers.
4. Scroll your **Following** page, `x.com/<your-handle>/following`, all the way down. Every person shown is added to the people you follow.
5. Open the extension's side panel. The **Network** card shows the counts, for example "842 of 1,200 followers (70%)", and updates live while you scroll.

The extension never scrolls, clicks, follows or opens anything for you, so the lists fill exactly as fast as you scroll. X loads long lists bit by bit; with thousands of followers the first full pass takes a while. After that, X lists your newest followers first, so scrolling until you reach people you've already seen is enough.

### Read the badges

Next to every post author on X (timeline, search results, replies, quoted posts) a badge shows the connection. Hover it for details and how complete the lists are.

| Badge | Meaning |
| --- | --- |
| 🤝 | Mutual: you follow each other |
| 🔭 | You follow them, they don't follow you |
| 👋 | They follow you, you don't follow back |
| 🎯 | Neither: someone new to connect with |

🎯 means "not in either list so far". Until both lists are complete, some 🎯 people may be followers you haven't scrolled past yet, so scroll both lists before going through search results for new people.

### How the lists stay correct

- Any people list on X that shows a **Follows you** label or a **Follow/Following** button (people search, likes, reposts) updates the lists, including people you have since unfollowed.
- Only the main column is read. The "Who to follow" sidebar is ignored, so suggestions never end up in your lists.
- People who unfollow you aren't removed automatically, because the extension only sees who is there, not who left. **Clear lists** in the Network card and a fresh scroll of both pages starts over.
- Switch the badges off with the toggle in the Network card. The lists stay in your Chrome profile and are never sent anywhere, including SubQ.

## How it fits together

| Path | What it is |
| --- | --- |
| `extension/` | The Chrome extension (Manifest V3, no build step) |
| `extension/content.js` | Finds reply boxes on X and Facebook, shows the buttons, reads the post being replied to |
| `extension/background.js` | Drafts file sync and the SubQ ranking requests |
| `extension/network.js` | Follower tracker: reads followers and following from the screen, adds the badges |
| `extension/store.js` | Storage, drafts pool, settings, icons |
| `extension/sidepanel.*` | The side panel |
| `extension/DRAFTING-RULES.md` | Your DOs and DON'Ts |
| `drafts/` | Draft text files and project facts |
| `drafts/used/` | Drafts you've posted, written by the side panel (not committed) |
| `make-drafts.js` | Builds `extension/drafts.json` and checks the drafts |
| `make-voice.js` | Builds `drafts/voice.md` from an X replies export |
| `make-icons.js` | Draws the toolbar icon PNGs |
| `.agents/skills/`, `.claude/skills/` | The `replenish-drafts` skill |

If the buttons stop appearing after a site update, the reply box detection is `findReplyBox` in `extension/content.js`; finding the post's text is `postTextFor`. If the follower lists stop filling, the people-card reading is `scanPeople` in `extension/network.js`.
